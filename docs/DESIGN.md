# FM160 单模块管理套件 — 设计方案（OpenWrt 25.x / fw4 / LuCI JS）

> 目标：为一台路由器上**唯一一个广和通 FM160** 提供模块管理、信号显示、QMI/MBIM/ECM 三模式拨号、短信收发、基站锁频、GNSS。
> 硬约束：**只适配 FM160**（不做通用多厂商框架）；**只允许 QMI / MBIM / ECM**，其余模式屏蔽；**AT 轮询必须克制**（高通 AT 脆弱）。
> 事实依据见 `AT-FACTS.md`（全部来自用户提供的三份广和通官方文档）。

---

## 1. 设计原则（先立规矩，再写代码）

| # | 原则 | 为什么 |
|---|---|---|
| P1 | **一个 AT 口，只能有一个属主。** 所有 AT 收发出 `fm160d` 一个进程串行完成，其它任何组件（LuCI、netifd proto、脚本、用户）一律走 ubus。 | 并发写同一 tty 是高通 AT 挂死/串响应的首要原因 |
| P2 | **能靠 URC 就不轮询；能靠 `/sys` 就不发 AT。** | 每条 AT 都是一次中断+串口事务 |
| P3 | **轮询分级 + 抖动 + 失败退避 + 熔断。** 不允许固定 1s 死循环查询。 | 固定高频轮询会把模块打到「不响应」 |
| P4 | **模式切换与拨号期间必须静默。** 全局静默窗，只允许当前序列自己的指令。 | 切换/激活期间插查询会污染状态机 |
| P5 | **一切写入前先探测设备真实能力**（`AT+XXX=?`）。绝不硬编码枚举值。 | 手册明说 mode/band 支持集依设备而定且手册有排版错误 |
| P6 | **不做「不可回头」的操作。** 无 AT 口的 USB mode 一律硬黑名单；任何持久化变更都带回滚记录。 | 用户已踩过「切完回不来」 |
| P7 | **降级要可见。** AT 卡住时 UI 必须明确显示「AT 降级/失联」，而不是显示旧数据假装正常。 | 避免误判 |

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ LuCI JS 前端  luci-app-fm160                                 │
│  概览·信号  拨号  短信  锁频  基站  GNSS  AT调试  设置        │
└───────────────┬──────────────────────────────────────────────┘
                │ rpcd / ubus（只读快照 + 动作）
┌───────────────▼──────────────────────────────────────────────┐
│ fm160d  —— 唯一的 AT 属主                                     │
│  ├ port_manager   串口发现(ttyUSB* 探 AT)、独占、断线重连      │
│  ├ tty_io         raw 115200 8N1 无流控、读写分离              │
│  ├ line_parser    行分帧 → 响应 / URC 分流                     │
│  ├ request_queue  优先级队列(交互 > 状态机 > 轮询)，同 cmd 去重 │
│  ├ scheduler      轮询分级 + 抖动 + 退避 + 静默窗 + 熔断        │
│  ├ state_cache    base/reg/signal/cell/ca/sms/gnss 快照        │
│  ├ urc_dispatcher +CMTI/+CDS/+CEREG/+C5GREG/+CGEREP → 事件     │
│  ├ prompt_txn     两阶段事务（等 "> " 提示符 → 写 PDU → 0x1A）  │
│  └ ubus "fm160"   方法 + 通知（state 变化主动推送）             │
└───────────────┬──────────────────────────────────────────────┘
                │ 用户态 netifd proto
     ┌──────────┼───────────┬────────────────┐
     ▼          ▼           ▼                ▼
  proto qmi  proto mbim  proto fm160      (EP 事件)
  (uqmi)     (umbim)     (ECM 自定义)     短信入库/转发
     │          │           │
     └──────────┴───────────┴──→ wwan0 / usb0 → 防火墙 zone (fw4)
```

**为什么前端只拿快照**：UI 的 `poll.add` 只读 ubus 里的缓存，绝不触发真实 AT。真 AT 只由 `fm160d` 按自己的节奏发。这样「UI 开着」对模块的额外负担 = 0 条额外命令，只是把既有轮询提速（见 §4）。

## 3. AT 传输层设计（本项目的核心价值）

### 3.1 串口操作规范

| 项 | 取值 | 说明 |
|---|---|---|
| 设备 | `/dev/ttyUSB*` | **不假设编号**：逐个打开发 `AT` 探 `OK`，认到的那个才用 |
| 参数 | 115200 / 8N1 / 无流控 | **不启用 RTS-CTS**（硬件未必支持，启用可能直接挂） |
| termios | raw，`VMIN=0 VTIME=1` | 避免阻塞读 |
| 行尾 | **`\r`** | FM160 标准；不发送 `\n` |
| 回显 | 解析层容忍（首行 == 命令则丢弃） | **不依赖 `ATE0`**：模块复位后回显会回来 |
| 错误码 | 初始化发 `AT+CMEE=2` | 拿到文字错误，便于诊断 |

### 3.2 单属主串行 + 优先级队列

- **不变量**：任意时刻最多 1 个 AT 事务在飞。
- 队列元素：`{prio, cmd, timeout_ms, expect, phase, cb}`
- 优先级：`0 = 交互（用户点击发起）` > `1 = 状态机（拨号/切换/短信）` > `2 = 轮询`
- **去重**：同一 `cmd` 已在队列中 → 合并（保留最新，把后来者的回调挂到前者）
- **饥饿保护**：优先级 2 的项若等待 > 30 s，提升为 1（防止用户连续操作把轮询饿死）

### 3.3 两阶段事务（`prompt_txn`）——短信必须

`AT+CMGS=<len>` 与 `AT+CMGW=<len>` 都不是「发完就收 OK」，而是：

```
TX: AT+CMGS=27\r
RX: >                       ← 提示符（无 \r\n）
TX: <PDU hex>\x1A           ← 必须以 Ctrl-Z(0x1A) 结尾，不用加 \r
RX: +CMGS: 42\r\nOK\r\n
```

⇒ 传输层必须原生支持「发命令 → 等提示符 → 再写裸数据 → 等终态」。这是硬需求，不能靠 shell 拼接。

**实现落点（2026-09-19，M3 落地时补记）**：传输层**一行都不用改**。at-daemon
的 `sendat` 已经有 `raw_at_content` —— 语义正是 hex → 裸字节、**不追加 `\r`**、
照常等 `end_flag`，第二阶段直接用它。缺的那一半在 `atq.c`：`struct at_req` 携带
`prompt[]` 与 `payload_hex[]`，`atq_issue()` 在 stage1 与 stage2 之间**不返回**，
所以两阶段是**一个队列项**，轮询插不进中间；载荷超长在提交前以 `-ENOSPC`
**拒绝而不是截断**（截断的 PDU 会被模组当成一条内容错误的合法短信）。
详见 `AT-FACTS.md` §12.1。

### 3.4 URC 处理

- 初始化：`AT+CNMI=2,1,0,0,0`（**只收 `+CMTI` 索引通知**）。
  **刻意不用 `CNMI=2,2`（直接投递 PDU）**：那会把整条 PDU 插进 AT 流，与在飞命令的响应互相污染。
- `AT+GTURCMODE=0,"<URC>"` 可按需**屏蔽最多 10 条**用不到的 URC（`+CMTI` 绝不可屏蔽）。
- URC 分类表：

| URC | 含义 | 处置 |
|---|---|---|
| `+CMTI: "SM",<idx>` | 新短信 | 入队 `AT+CMGR=<idx>`（prio 1）→ 解析入库 → 按策略 `AT+CMGD` |
| `+CDS:` | 送达报告 | 同上，打标 |
| `+CEREG: <stat>` / `+C5GREG: <stat>` | 注网状态变化 | 只更新状态；**仅当 stat 变化**才补一次 `AT+CSQ` |
| `+CGEREP: <ev>` | 数据链路事件 | 触发一次状态刷新 |
| 其它带 `+`/`^` 开头且不在等待列表 | 未知 URC | 记日志（限速），不中断当前事务 |

### 3.5 轮询分级表（**默认值，可配**）

「空闲」= 无 UI 连接；「前台」= 有 LuCI 页面在轮询。（`fm160d` 通过 ubus 订阅者数量判断）

| 级别 | 内容 | 命令 | 空闲 | 前台 | 退避 | 备注 |
|---|---|---|---|---|---|---|
| **E** | 事件 | URC（§3.4） | — | — | — | 不轮询，优先 |
| **P0** | 注网 + 信号 | `AT+CEREG?` `AT+C5GREG?` `AT+CSQ` | 15 s | 5 s | ×2 → 120 s | 最核心 |
| **P1** | 服务/邻区 | `AT+GTCCINFO?` | 仅前台 60 s | 10 s | ×2 → 300 s | 一条拿全 RSRP/RSRQ/SINR + 邻区 |
| **P2** | 流量 | 读 `/sys/class/net/<if>/statistics/{rx,tx}_bytes` | 5 s | 2 s | — | **0 条 AT** |
| **P3** | CA | `AT+GTCAINFO?` | 仅前台 120 s | 30 s | ×2 | 要才查 |
| **P4** | 慢变/身份 | `AT+CGMI/CGMM/CGMR/CGSN/CFSN/CCID/GTUSBMODE?/GTACT?/CPMS?/CPIN?` | **不轮询** | 不轮询 | — | 附着时各 1 次 + 手动刷新 |
| **P5** | GNSS | `AT+GTGPS="GGA"` | 关闭 | 1–5 s | ×2 → 30 s | 仅 GNSS 页可见或采集开启时 |
| **Q** | **静默窗** | 全部挂起 | — | — | — | 见 §3.6 |

抖动：每个 poller 的实际间隔 = `interval × (0.8 ~ 1.2)` 随机 ⇒ 避免多条命令长期同相位叠在一起。

### 3.6 静默窗（Quiet Window）

| 触发事件 | 挂起时长 |
|---|---|
| 拨号序列（`GTWWAN`/`GTRNDIS` 激活） | 整个序列周期，最长 210 s |
| 断线重连 | 30 s |
| `AT+CFUN=1,1`（模块软重启） | 45 s |
| USB mode 切换 | 30 s 起，**并等待端口重新枚举**（实测可能 10–90 s） |
| `AT+COPS=?` 全制式扫描 | 60 s（扫描期间模块极忙） |
| 锁小区后重启流程 | 随重启 |
| 用户手动发 AT（调试页） | 10 s（避免用户命令与轮询撞车） |

### 3.7 熔断与降级

```
连续超时 3 次  → 暂停全部轮询 60 s，状态置 AT_DEGRADED，UI 显黄
  └ 恢复探测：只发一条 "AT"（3 s 超时）
连续超时 10 次 → AT_DEAD：停止一切自动 AT（含 URC 之外的刷新），UI 显红
  └ 只保留：手动 AT 页、模式/复位等恢复入口
任一次成功     → 计数清零，状态回 OK
```

- **轮询失败不计入熔断**（模块忙导致的单次失败是常态，会掩盖真故障）；只有**超时/无应答**计数。
- 每次熔断/恢复都写 syslog + UI 提示，绝不静默。

### 3.8 观测：进程内日志环与支持包（M6）

**问题**：`fm160_log()` 只做一件事——把行交给 `vsyslog()`。于是这个守护进程对自己的日志**一点办法也没有**：logd 的环是全机共用的、重启即丢、进程内读不到。结果是「把日志发我看看」这个请求，守护进程自己答不了，而报障只能到「页面白屏」为止。

**做法**：在 `vsyslog()` 旁边挂一个 **128 行定长环形缓冲**（`FM160_LOG_RING_LINES`），新增**只读** ubus 方法 `fm160 diagnostics`，返回一份**纯文本**支持包：头部（版本/时间/uptime/日志级别/丢弃行数）+ 各子系统状态 + 日志尾。

五个刻意的取舍，每个都对应一种会静默出错的方式：

| 取舍 | 为什么 |
|---|---|
| **不写文件** | overlay 上的日志要轮转，轮转失败会填满 flash，而这是台路由器。也不放 `/tmp`：tmpfs 正是内存耗尽时最该留下证据的地方 |
| **在级别闸门之后入环** | 环里就是 syslog 收到的那份。于是 `log_level` 对导出同样有效——你在 logread 里会看到什么，下载到的就是什么；级别打印在头部，缺席的 DEBUG 行有解释而不是谜 |
| **纯层 `diag.c`** | 无 I/O、无全局、**时钟由调用方传入**（`now_ms` / `uptime_ms` / 墙上时间字符串）。⇒ 输出逐字节可复现，因而可断言；测试二进制里不需要有守护进程 |
| **返回长度而非直接写** | 定容不够时**拒绝**（返回 −1）而不是截断。半份报告比没有更糟：读者无从知道缺了哪几节。测试用哨兵字节证明越界未写 |
| **只读，绝不碰模组** | 这是硬约束不是礼貌。最诱人的做法是「顺手重读一遍模组」，而在本硬件上**重读恰恰会消灭故障**——它开静默窗、重置轮询阶梯、改掉 bug 依赖的时序。会改变机器的诊断不是诊断 |

**文本而不是 blob**：消费方是**写报障的人**，不是打开页面的那个人。blobmsg 对页面更方便，对「贴进论坛」毫无用处。所以回复里 `text` 是逐字的那份文本，页面同时提供下载与复制。

**「从未发生过」与「0」必须不同**：`last_ok=0` 打 `never`，`=now` 打 `0.000 s ago`；`FM160_NONE`（−1000000）打 `-`；只填了 `time()` 的时钟打 `(clock not set)` 而不是 1970。这些若混同，读报的人会得出相反结论——「复位 0 次」看起来像功能正常。

**定容是算出来的**：`FM160_DIAG_BUF_MAX = FM160_DIAG_HEAD_MAX(6144) + 128 × 224`。主机侧测试构造**最坏情况**（满环 + 每行取满 + 每条字符串取满）实测 **32 192 / 34 816 B**，并断言装得下。所以多加一节而没重算这个数，是**门禁失败**而不是设备上才炸。

## 4. 拨号

### 4.1 三模式矩阵

| 用户选择 | USB mode（白名单） | 主机驱动 | 网卡 | OpenWrt 接入 |
|---|---|---|---|---|
| **QMI** | 32 / 17 / 25 / 22 | `qmi_wwan` | `/dev/cdc-wdm0` + `wwan0` | 原生 `proto qmi`（uqmi） |
| **MBIM** | 30 / 29 | `cdc_mbim` | `/dev/cdc-wdm0` + `wwan0` | 原生 `proto mbim`（umbim） |
| **ECM** | 33 / 18 / 23 / 19 | `cdc_ether` | `usb0` | **自定义 `proto fm160`** |

（首选排在前：优先选「无 ADB、接口最少」的那个。）

### 4.2 ECM 为什么要自定义 proto

ECM 不是「网卡起来就能 DHCP」，**必须先在模块内部激活数据调用**：

```
fm160_ecm_setup():
  1) AT+CPIN?                       → READY
  2) AT+CREG? / AT+CGREG? / AT+CEREG?  → 1 或 5
  3) AT+CGDCONT=<cid>,"IP","<apn>"  （或 IPV4V6）
  4) 探测激活命令：AT+GTWWAN=? 或 AT+GTRNDIS=? 哪个 OK 用哪个   ← 官方文档自相矛盾，必须运行期探测
  5) AT+GTWWAN=1,<cid>
     结束判定：OK / ERROR / "+GTWWAN: 0" / 210 s 超时（四者之一）
  6) 轮询 AT+GTWWAN? 取 IP；未拿到连续 5 次 → 回第 1 步
     连续 5 次拨号失败 → 复位模块（走 fm160d，不裸发 AT）
  7) 网卡拿到 IP → 交给 netifd 的 DHCP 接管
teardown: AT+GTWWAN=0,<cid>
```

⚠️ 官方红线：**断开只能靠 `AT+GTWWAN=0,<cid>`**；直接拔线/断电/重启模块不算断开。

### 4.3 连接守护

- 判活用**真实业务**（按策略 ping 或 dns 查询），不用「网卡 UP」当成功。
- 掉线重连阶梯：立刻重试 → 5 s → 15 s → 60 s → 300 s（封顶），并先做一次「轻量复位」：
  `AT+CGACT=0,<cid>` → `AT+CGACT=1,<cid>` 或 `GTWWAN=0,<cid>` / `=1,<cid>` 重激活。
- 只有阶梯耗尽才升级到 `AT+CFUN=1,1`。**复位次数计入持久计数**（写 uci），24 h 内超过 N 次 ⇒ 停止自愈并告警，防打转。

## 5. USB mode 切换安全状态机（防「切完回不来」）

### 5.1 硬黑名单 / 白名单

| 集合 | 成员 | 依据 |
|---|---|---|
| **硬黑名单（永久禁止）** | `20`（仅 Modem 口）、`24`（RNDIS，无 AT 口）、`28`（MBIM only，无 AT 口）、`31`（无 AT 口） | 切进去后路由器**失去 AT 通道**，无法再切回 |
| **允许** | QMI {32,17,25,22} / MBIM {30,29} / ECM {33,18,23,19} | 均含 AT 口 |
| **额外允许（恢复用途，UI 默认隐藏）** | `21`（MODEM+AT，无数据口） | 有 AT 口，可作紧急恢复落点 |

**双重门槛**：目标必须在**设备 `AT+GTUSBMODE=?` 返回的支持集** ∩ **我们的白名单**里。任一不满足 → 拒绝执行。

### 5.2 状态机

```
IDLE ──用户选择──▶ CONFIRM ──▶ PRECHECK ──▶ APPLY ──▶ REBOOT ──▶ VERIFY
        (二次确认，      拒绝则退回 IDLE      (失败回滚)
         明示风险)

PRECHECK
  1) cur   = AT+GTUSBMODE?
  2) sup   = AT+GTUSBMODE=?
  3) 校验 target ∈ sup ∩ whitelist；target == cur → 直接结束
  4) 记录回滚点：uci set fm160.switch.rollback_mode = cur
  5) 若数据已连接 → 先正常断开（GTWWAN=0 / mbim disconnect）
  6) 停 netifd iface，进静默窗

APPLY
  7) AT+GTUSBMODE=<target>  → 期望 OK（其它一律视为失败并回滚）
  8) uci set fm160.switch.pending = <target> / pending_since = <ts>
  9) 触发模块重启（优先后续由 USB 重新枚举自然完成）

VERIFY（fm160d 每次启动都跑）
 10) 找 AT 口
     找到 且 AT+GTUSBMODE? == target  → 清 pending，重建 iface，通知 UI 成功
     找到 但 != target                → 自动回退到 rollback_mode（**只回退一次**），告警
     找不到 AT 口                     → 置 SWITCH_STUCK：
                                        UI 红色常驻告警 + 明确指引（人工用 ADB/DIAG 口恢复）
                                        不再自动重试，避免反复重启打转
```

### 5.3 UI 侧要求

- 下拉框**只列白名单里的 mode**，且标注「当前」。
- 显示每个选项的真实含义（如 `32 = DIAG+MODEM+AT+PIPE+RMNET`），不让用户背数字。
- 切换到黑名单里曾出现过的编号时，直接不给选项。
- 切换按钮走**二次确认弹窗**，文案说明「将重启模块、期间断网约 30–90 s」。

## 6. 短信

| 项 | 设计 | 理由 |
|---|---|---|
| 模式 | **PDU 模式**（`AT+CMGF=0`） | 中文必须 UCS2；文本模式有损 |
| 存储 | `AT+CPMS?` 探测支持的存储，优先 `"ME"`，回退 `"SM"` | 写死会 ERROR |
| 接收 | `AT+CNMI=2,1,0,0,0` → `+CMTI` → `AT+CMGR=<idx>` | 见 §3.4，避免 PDU 污染 AT 流 |
| 发送 | **主路径 `AT+CMGW` + `AT+CMSS`**；备路径 `AT+CMGS` | 两者都要 `>` 提示符，但 CMGW 把「写入」与「发送」解耦，失败可重试发送而不用重建 PDU |
| 长短信 | 自己组 UDH 分段（默认最多 3 段，8-bit 参考号） | 手册未内置自动分段 |
| 编码 | GSM7 优先，含非 GSM 字符 → UCS2 | 省 30% 短信长度 |
| 入库 | 解析后写入自有存储（`/etc/fm160/sms/` JSONL + 内存索引），并提供去重（按 SCTS+发件人+PDU hash） | SIM 空间有限、模块存储会被清 |
| 清理 | 可配「读后即删」/「保留 N 天」/「保留 N 条」 | 防止 `+SMMFULL` |
| 送达报告 | 可选（`AT+CSMP` + `+CDS`） | 非默认，避免额外 URC |
| 转发 | 可选：转发到邮件/Webhook（复用现成 `agent-mail` 亦可） | 分期做 |

**注意**：`AT+CNMA`（新消息确认）仅在 `AT+CSMS=1` 且用 direct delivery 时才需要；我们走 `+CMTI` 路径，**不开启**需要确认的模式，少一个失败点。

**实现差异（2026-09-19，M3 落地后回填）。** 下表是设计与最终实现的出入，逐条
给理由 —— 一篇与代码不符的设计文档，比没有文档更会误导人：

| 项 | 设计 | 实现 | 为什么改 |
|---|---|---|---|
| 发送主路径 | `AT+CMGW` + `AT+CMSS` | **`AT+CMGS`** | 每个 AT 事务 = 一次等 `>` + 一次等终态，多段发送就是 2×N 次等待，是全链路最脆的地方；CMGW/CMSS 把它变成 4×N 次，还额外要求**存储可用** —— 而存储正是无卡时最先失败的那一环。CMGS 一步完成，少一半事务、少一个前提。 |
| 长短信上限 | 3 段 | **4 段**（`SMS_PDU_SEG_MAX`） | 4×153 = 612 个字符，覆盖常见的验证码与通知长文；再长就该走别的通道。前端用同一常量做预览，超出时**拒绝发送而不是截断**。 |
| 去重键 | SCTS + 发件人 + PDU hash | **storage + index + 发件人 + 正文** | 模组的索引会被**回收**（删掉一条，下一条可能落进同一个槽），索引相同并不说明是同一条；而 SCTS 只有两位年份、粒度到秒，同秒两条就撞车。正文比较是唯一不会误吞新消息的判据 —— 代价是「同一正文的两条不同消息」会被合并，这个概率远低于误吞。 |
| 保留策略 | 读后即删 / 保留 N 天 / 保留 N 条 | **本地 64 条**（环形）；模组侧只在用户显式删除时 `AT+CMGD` | 自动删模组上的消息是不可逆的，而「存储会不会满」这件事在没有 SIM 的机器上根本无法验证。默认不动模组、只留本地，是这台机器上唯一能被证实的选项。 |
| 送达报告 | `AT+CSMS=1` + `+CDS` | **未实现**（`+CDS` 只被识别并记日志） | 需要额外 URC 与状态机，且无 SIM 无法验证。识别而不解析，是为了让它出现时留下证据，而不是被当成垃圾吞掉。 |

⚠️ 另有两处**实现里修掉、而本设计文档原本没写**的边界，记在这里免得后人重犯
（细节见 `AT-FACTS.md` §12.8）：

* **UDH 填充位只属于 GSM7**。UCS2 是字节流、头本身已是整字节，再加填充就是
  141 octets > 140 上限。把「UDH 后面要补到 7 bit 边界」当成通用规则写，单条
  短信不会暴露任何问题（单条没有 UDH）。
* **分段时字节游标必须回退**。一个字符放不下时它的字节已经被消费掉了，不回退
  会让第二段起每段少首字符、末段少尾字符。

## 7. 锁频 / 锁小区

### 7.1 频段与 RAT

- 读：`AT+GTACT?`；能力：`AT+GTACT=?`
- 写：`AT+GTACT=<rat>[,<pref1>[,<pref2>]][,<band...>]`
- 频段编码（仅用于把设备返回的数字翻译成人话）：**LTE = 100+n，NR = 500+n，UMTS = n**
- 只改频段不改 RAT 时，前三个参数留空：`AT+GTACT=,,,103,141`
- 生效：立即（无需重启），但**必然掉网** ⇒ 变更前后各开一次静默窗，随后触发重连。

### 7.2 锁小区

```
AT+GTCELLLOCK=<mode>,<rat>,<type>,<earfcn>[,<PCI>][,<scs>[,<nrband>]]
```

- 典型用法：从 `AT+GTCCINFO?` 的服务小区里取出 `earfcn` + `PCI`，加锁。
- ⚠️ **三条硬约束必须在 UI 上明确提示**：
  1. 下发后**必须重启模块**（写 EFS，重启才生效）
  2. **换 SIM 前必须先关闭本功能**
  3. 关闭 = `AT+GTCELLLOCK=0`
- UI 提供「一键锁当前服务小区」，自动填 `earfcn`/`PCI`/`scs`/`nrband`，避免手输错。
- 锁小区流程与 §5 的重启/VERIFY 状态机共用一套逻辑。

### 7.3 邻区与 CA

`AT+GTCCINFO?` 已含最多 10 个邻区；`AT+GTCAINFO?` 给载波聚合信息。两者都只在前台/展开时查询。

## 8. GNSS

- 开关：`AT+GTGPSPOWER=0|1`（**掉电不保存** ⇒ 若用户勾选「开机自启」，由 `fm160d` 在附着后补发）
- 卫星组合：`AT+GTGPSCFG=2,<v>`，默认建议 `14`（GPS+BDS+GAL+GLO+QZSS 全开）；存「掉电保存」
- AGPS：`AT+GTGPSEPO=1`（MSB）；服务器 `AT+GTAGPSSERV="supl.qxwz.com",7276`（默认值即可）
- 读：`AT+GTGPS="GGA"` / `"RMC"`（定位/速度）/ `"GSV"`（星座可见卫星）
- 轮询：**只在 GNSS 页可见或采集开启时**按 P5 级别轮询（1–5 s）；离开页面立即停，防止长期占用 AT
- 解析：GGA（定位质量、HDOP、高度）→ RMC（时间、速度、航向）→ GSV（每星座卫星数与 SNR 条形图）
- 可选增强：把 NMEA 转发到 TCP `10110`（供地图软件直接连），但**默认关闭**

- `poll.add` 的间隔**不小于**服务端对应级别的前台间隔（避免前端比后端还急）。

- 危险动作（模式切换、锁频、复位）统一走同一个「确认弹窗 + 后果说明」组件。
